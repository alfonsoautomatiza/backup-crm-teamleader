    Créer une sauvegarde Teamleader avec Backup TL¶

    Utilisez ce guide pour préparer un dossier de destination, exécuter une sauvegarde depuis la fenêtre principale et vérifier le résultat. Pour automatiser le processus, consultez l'utilisation depuis la console.

    flowchart LR
    A["Préparer les identifiants"] --> B["Configurer la sauvegarde"]
    B --> C["Exécuter la sauvegarde"]
    C --> D["Surveiller la progression"]
    D --> E["Vérifier le résultat"]
    E --> F["Fichiers .encrypted vérifiés"]

    Chemin rapide¶

    1. Installez Backup Teamleader et ouvrez l'application.
    2. Saisissez Client ID et Client Secret si la fenêtre d'identifiants apparaît.
    3. Choisissez un dossier de destination vide ou dédié à cette sauvegarde.
    4. Conservez Reculer les jours à 0 et Refaire la copie complète désactivé pour une exécution incrémentale normale.
    5. Cliquez sur Exécuter la sauvegarde.
    6. Attendez Processus terminé correctement et vérifiez les fichiers .encrypted du dossier.

    Première exécution

    N'activez pas les pièces jointes ni la conversion de fichiers lors du premier test. Ajoutez chaque option séparément après avoir confirmé que la sauvegarde de base se termine correctement.

    Préparer les identifiants¶

    Au démarrage, Backup Teamleader peut afficher une fenêtre avec les champs Client ID et Client Secret. Cliquez sur Vérifier après avoir rempli les deux champs. L'application enregistre les valeurs et continue l'autorisation ; si elle ne peut pas vérifier à ce moment-là, elle affiche le détail disponible.

    Vérification Critère
    Données visibles Ne documentez ni ne partagez de vraies clés, jetons, mots de passe ou identifiants sensibles.
    Confirmation Attendez que l'outil accepte les identifiants avant de lancer la sauvegarde.
    Preuve Si vous avez besoin d'une capture, masquez les valeurs et ne laissez visibles que les étiquettes, champs et boutons.

    Protégez les identifiants

    Ne partagez pas de captures, fichiers de configuration ou journaux contenant Client ID, Client Secret ou jetons d'autorisation.

    Configurer la sauvegarde¶

    Avant de cliquer sur le bouton d'exécution, vérifiez ces champs.

    Champ ou option Utilisation opérationnelle Recommandation
    Dossier de destination Définit où les fichiers .encrypted sont enregistrés. Utilisez un chemin avec des permissions d'écriture et un espace suffisant. Une nouvelle installation propose C:\backup_teamleader.
    Reculer les jours Permet de récupérer des changements antérieurs. Conservez 0 si vous n'avez pas besoin d'étendre la plage.
    Refaire la copie complète Force une sauvegarde complète depuis le début. Utilisez lorsque vous souhaitez reconstruire la sauvegarde ou écarter une exécution incrémentale.
    Télécharger les pièces jointes Active le téléchargement des pièces jointes lorsque vous saisissez la clé correspondante. Vérifiez au préalable que vous disposez de la clé et de l'espace disque.
    Exportation vers Excel - dossier de destination Convertit les fichiers chiffrés en un format lisible. L'implémentation actuelle génère .json, bien que l'interface utilise le nom « Excel ». La confirmation demande le Client Secret.

    Consultez Configurer les options de sauvegarde pour décider quand utiliser chaque champ.

    Exécuter et surveiller¶

    1. Cliquez sur Exécuter la sauvegarde lorsque la configuration est prête.
    2. Observez la zone de console ou d'état pour vérifier la progression.
    3. Attendez le message de fin avant d'ouvrir ou de déplacer les fichiers générés.
    4. Utilisez Arrêter uniquement si vous devez annuler. Le bouton demande l'annulation ; attendez que l'état indique Annulé.

    N'interrompez pas les fichiers

    Ne fermez pas l'application et ne déplacez pas le dossier de destination pendant que la sauvegarde est en cours. Une interruption peut laisser une exécution partielle.

    Verifier le resultat¶

    À la fin, vérifiez le résultat avant de considérer la sauvegarde comme valide.

    Preuve Quoi vérifier Où regarder
    État final Que l'exécution s'est terminée correctement ou indique une annulation contrôlée. Étiquette d'état ou console intégrée.
    Fichiers générés Que des fichiers .encrypted existent et que la date correspond à l'exécution. Dossier sélectionné dans Dossier de destination.
    Pièces jointes Que les fichiers attendus ont été créés ou mis à jour si vous avez activé l'option. Dossier de destination ou sous-dossiers générés par l'outil.
    Conversion lisible Que des fichiers .json existent dans le dossier choisi. Dossier indiqué dans le bloc d'exportation.
    Journal et état Qu'il n'y a pas de messages d'erreur et que l'état final est cohérent. Console intégrée et journal disponible dans l'installation.

    Un dossier avec des fichiers ne prouve pas une sauvegarde correcte

    Vérifiez également l'état final et les dates. Si l'exécution s'est terminée avec des erreurs ou a été annulée, traitez le résultat comme partiel.

    Liste de contrôle avant d'utiliser Backup TL¶

    • Backup TL est installé ou extrait d'une version spécifique de GitHub Releases.
    • Les identifiants nécessaires sont disponibles et ne sont saisis que dans l'outil.
    • Le dossier de destination existe, a des permissions d'écriture et un espace suffisant.
    • Vous avez décidé si la sauvegarde sera incrémentale ou complète.
    • Vous avez décidé de télécharger les pièces jointes.
    • Vous avez décidé de convertir les fichiers en JSON.
    • Vous vérifierez l'état final avant de fermer l'outil.
    • Vous conserverez le journal si l'exécution doit être auditée.

    Étape suivante¶

    Si la sauvegarde de base s'est terminée correctement, consultez les options de sauvegarde complète, recul des jours et pièces jointes. Si une erreur est apparue, allez au Dépannage avant de réessayer.
