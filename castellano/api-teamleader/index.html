    Credenciales de Teamleader para Backup TL¶

    Backup Teamleader necesita un Client ID y un Client Secret para iniciar la autorización con Teamleader. La aplicación muestra esta ventana cuando todavía no puede verificar el acceso.

    Preparar la integración¶

    1. Abra el portal de integraciones de Teamleader. Es el mismo destino que abre el botón abrir datos API de Backup Teamleader.
    2. Abra la integración que utilizará para la copia o cree una siguiendo la documentación oficial de OAuth 2.
    3. Obtenga el Client ID y el Client Secret desde la configuración de esa integración.
    4. Revise la URI de redirección y los permisos antes de copiar las credenciales a Backup Teamleader.

    URI de redirección¶

    Teamleader exige que la redirect_uri coincida exactamente con una URI autorizada en la configuración de la integración. La dependencia incluida en la build actual abre un servidor HTTP local en el puerto 5000 y solo acepta la ruta /callback.

    El repositorio no permite determinar si la integración publicada registró localhost, 127.0.0.1 u otro hostname. Copie y conserve la URI exacta que figure en la integración existente; no intercambie esos hostnames aunque apunten al mismo equipo.

    No adivine una redirect URI nueva

    El flujo actual no envía redirect_uri de forma explícita al construir la URL de autorización. Si la integración no tiene ya una URI compatible con el puerto 5000 y la ruta /callback, solicite al responsable de la build el valor validado antes de crear o cambiar la integración.

    Permisos y scopes¶

    Teamleader asigna scopes por familia de endpoints. Active únicamente los necesarios para las entidades que esta instalación debe copiar. La documentación oficial confirma, por ejemplo, los scopes users, deals, projects e invoices para sus respectivos endpoints.

    El modelo actual también contempla empresas, contactos, productos, notas de crédito, suscripciones y archivos adjuntos. El conjunto final puede depender de la licencia y configuración de la build, por lo que no existe una lista única verificable dentro de este repositorio. Revise en la referencia de la API de Teamleader el scope requerido por cada entidad habilitada; incluya archivos solo si utilizará la descarga de adjuntos.

    Autorizar Backup Teamleader¶

    1. Complete Client ID.
    2. Complete Client Secret. El campo oculta el valor de forma predeterminada.
    3. Pulse Verificar.
    4. Complete la autorización en la ventana del navegador que abre la aplicación.
    5. Mantenga Backup Teamleader abierto mientras espera el retorno local a /callback.
    6. Espere el mensaje de confirmación o de verificación pendiente.

    Si Teamleader informa que la URI no coincide, compare el valor completo con la configuración de la integración. Si responde 403 al consultar una entidad, revise el scope de esa entidad antes de repetir todo el proceso.

    No exponga el secreto

    No envíe el Client Secret por correo, chat o capturas. Tampoco publique config.ini ni registros que puedan contener datos de autorización.

    Checklist¶

    • El Client ID y el Client Secret proceden de la integración correcta.
    • La URI registrada es compatible con el listener local en el puerto 5000 y la ruta /callback.
    • La integración tiene los scopes de todas las entidades que se copiarán.
    • Ambos campos están completos antes de pulsar Verificar.
    • La aplicación ha continuado con la autorización o ha mostrado el detalle de la verificación pendiente.
    • No se han compartido valores reales en capturas o incidencias.

    Siguiente paso¶

    Vuelva a la guía de la primera copia y prepare la carpeta de destino.
